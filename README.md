ДЗ 12. Телефонна книга
🎯 Мета завдання
Реалізувати односторінковий застосунок “Телефонна книга” на React без Redux та React Router, з можливістю:
переглядати список контактів;
створювати нові контакти через модальне вікно;
редагувати існуючі контакти через модальне вікно;
видаляти контакти;
зберігати всі дані в localStorage так, щоб після перезавантаження сторінки контакти не зникали.
📦 Технологічні вимоги
React (функціональні компоненти + хуки).
Formik – для роботи з формами створення/редагування контакту.
React Bootstrap – для верстки (Layout, Button, Input, Modal, Table/List тощо).
PropTypes – для типізації пропсів компонентів.
classnames – за потреби для керування класами.
lodash – за потреби (наприклад, для debounce пошуку, сортування і т.д.).
localStorage – для збереження списку контактів.
https://react-international-phone.vercel.app/ для створення інпуту з номером телефону
Заборонено використовувати Redux та React Router. Весь функціонал – на одній сторінці.
📑 Структура даних контакту (мінімум)
Контакт повинен містити щонайменше такі поля:
id (string або number, унікальний ідентифікатор);
name (string) – ім’я контакту (обов’язкове поле);
phone (string) – номер телефону (обов’язкове поле);
email (string, необов’язкове, але з базовою валідацією, якщо заповнене).
Можна додати додаткові поля: company, position, notes – за бажанням.
🖼 Основні UI-вимоги
Головний екран
Список контактів у вигляді таблиці або карти (Card / List).
Кнопка “Додати контакт” (Add contact) – відкриває модальне вікно створення.
Для кожного контакту: відображати ім’я, телефон, email (мінімум).
Для кожного контакту: кнопки “Редагувати” та “Видалити”.
Модальне вікно створення контакту
Використати React Bootstrap Modal.
Всередині модалки – форма на Formik.
Поля: name, phone, email (мінімум).
Валідація:
name – обов’язкове (не порожнє).
phone – обов’язкове (мінімальна перевірка формату, наприклад, довжина).
email – якщо заповнене, має відповідати формату email.
Кнопки: “Зберегти” (submit) та “Скасувати”.
Після успішного сабміту – контакт додається у список, модалка закривається, дані зберігаються у localStorage.
Модальне вікно редагування контакту
Відкривається при натисканні “Редагувати” біля конкретного контакту.
Повинні бути підставлені поточні значення полів контакту.
Ті самі правила валідації, що й при створенні.
Після сабміту – контакт оновлюється у списку, зміни зберігаються у localStorage.
Видалення контакту
При натисканні “Видалити” – або модальне підтвердження, або confirm() (за простим варіантом).
Після підтвердження – контакт видаляється зі списку й localStorage.
Пошук (бажано, але можна як опція)
Поле пошуку над списком контактів (по name та/або phone).
Фільтрація списку у реальному часі.
Можна використати lodash.debounce для оптимізації.
💾 Робота з localStorage
При першому завантаженні сторінки застосунок має:
прочитати дані з localStorage (наприклад, ключ phonebook_contacts);
якщо там є контакти – ініціалізувати стан з ними;
якщо немає – стартувати з пустого списку або кількох демо-контактів.
При будь-якій зміні (створення, редагування, видалення):
оновлювати стан у React;
одразу синхронізувати список контактів у localStorage.
⚙️ Технічні деталі реалізації (рекомендація)
Використати один “root” компонент, наприклад App, де:
зберігається стан списку контактів (useState);
відбувається ініціалізація зі сховища (useEffect + localStorage.getItem);
відбувається збереження в localStorage при зміні списку (useEffect + localStorage.setItem).
Окремі компоненти:
ContactsList – відображення списку контактів.
ContactRow або ContactCard – окремий контакт.
ContactFormModal – модалка + форма Formik (можна один компонент, який працює як для створення, так і для редагування, через пропси mode + initialValues).
Усі компоненти мають мати коректно описані propTypes.
